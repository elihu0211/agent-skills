# 簡報風格：配色、版面與寫法

範本的實際值在 [`assets/deck-template/`](../assets/deck-template)（分層見 [patterns.md](patterns.md)「引擎分層」）；本檔說明為什麼這樣用。字數上限與區塊欄位見 [patterns.md](patterns.md)。

## 版面骨架

外觀的載體是真正的 PPTX 範本（佈景主題、母片、版面；見 [patterns.md](patterns.md)「範本」）。下面是骨架的數值，都來自 `tokens.toml`。

16:9（13.333 × 7.50 in），白底。每張內容頁由上而下：章節標籤（11 pt，主色）→ 主標題（25.5 pt 粗體，寫結論句）→ 內容區（上緣 1.70 in，安全底線 6.85 in）→ 頁尾細線（7.00 in）→ 簡報短題與頁碼。單一區塊的頁面垂直置中；`note` 釘在底部。封面只有類別、題名、副題與作者（可省略），不放日期與機密字樣。

## 色票語義

顏色只表示語義，一個意思一個顏色，全份簡報一致；若同專案另有 PDF 文件或圖，兩邊共用同一份 `tokens.toml`，意思才會一致。

| `kind` | 語義 | 何時用 |
| :--- | :--- | :--- |
| `blue` | 資料與結構 | 資料、系統元件、主流程；主色也用在封面細線、章節標籤與步驟序號 |
| `green` | 系統確定 | 由規則或系統確定的結果、通過驗證、已落實 |
| `amber` | 只給候選 | 系統只提供候選、待人確認 |
| `red` | 須人判斷或失敗 | 問題、攔截、風險、違規 |
| `gray`、`white` | 中性 | 說明、背景、預設 |
| `dark`、`solid_dark` | 墨色強調 | 出發點與收斂點，不帶語義 |

白底上的小字用語義色的 `text` 深色版（對比 4.5 以上），線與填滿用 `main`，大面積底用 `lite`。粗體段落放在綠色標題卡裡會改成墨色，保持可讀；語義儲存格（表格）保留語義字色。

## 幾何

卡片與節點圓角 3 pt，線寬 0.75（細線、分隔）／1.0（一般）／1.5（語義卡片）pt，不用陰影。連線一律直角，箭頭向終點；連線標籤的文字框透明。

## 版式選擇

| 要說的事 | 用 |
| :--- | :--- |
| 先講完結論 | `steps` ＋ `banner` |
| 問題與痛點 | `banner` ＋ `cards`（紅） |
| 系統怎麼接起來 | `arch_graph`（附 `note`） |
| 一件事的先後 | `flow`；跨角色用 `swimlane` |
| 狀態怎麼變 | `arch_graph`（節點＝狀態，邊＝轉換） |
| 方案怎麼比 | `table`（綠＝選它的理由，紅＝缺點） |
| 責任分界 | `layers` |
| 數字怎麼來 | `bench_chart`（寫明示例或實測、未驗證的部分） |
| 何時做什麼 | `timeline_diagram` |
| 真的長什麼樣 | `shots`（實際截圖，附白話圖說） |
| 結論與風險 | `columns`（綠＝驗收、紅＝風險） |

## 實際畫面

畫面一律用實際程式的截圖，不手繪示意，也不用 AI 生成的假畫面。用示範資料截（租戶、信箱、金鑰都是假的），視窗 1200×720、裝置像素比 2；扁長版面用 `crop` 取上緣，不另存裁好的圖。圖說用白話描述畫面在做什麼，截圖上改不了的字（選單、示範資料）不用解釋。畫面做不到的（例如需要外部服務才有的狀態）直接在頁面寫「本頁為未開啟某功能的狀態」，不補假圖。

## 白話命名

投影片與講稿備註不顯示倉庫名稱與代碼名稱（服務代號、端點與路徑、設定鍵、資料表與欄位、檔名）：讀者看不懂。改成白話的功能名稱，例如「平台服務」「營運後台」「證據接地服務」。學術與標準名詞（ISO/IEC 17788）與通用工具名（PostgreSQL、Kubernetes）讀者查得到，可以保留。給維護者的 README 與問答稿可以寫路徑。`scripts/lint_names.py` 擋 snake_case、檔名與路徑，專案專屬的倉庫與服務代號用 `--deny` 帶入。

## 作者欄

作者的處理照 Quarto 的分層中繼資料（專案層預設、文件層覆寫）：預設寫在 `defaults.toml`，多份簡報共用同一份引擎時只寫一次；規格不寫 `author` 就用預設，寫了用規格的，寫空字串代表沒有，封面不印那一行。不要在每份規格重抄同一個字串，也不要另造「@鍵」之類的間接引用。給客戶與對外的說明通常不署名或署產品名，學位與內部報告署報告人；姓名與單位要拆開時，加兩個欄位，不要擠進同一個字串。

## 不標進度

簡報頁面與講稿只描述完成後的長相，不寫「規劃中」「目標流程」「尚未實作」「待核對」。程式現況、未定事項與待核對寫在該簡報的維護者文件，報告前由人核對。研究與評估報告的限制與未竟之處是研究內容，照寫，不屬於這一條。

## 講稿備註

鋪陳、背景與口頭引導寫進備註（規格的第四欄），投影片只留骨架、數據與圖形。備註同樣不寫代碼名稱；寫明數字出處與是實測、示例或估算。

## 驗證

1. `uv run assets/deck-template/build_deck.py out.pptx`（可加 `--pdf`，macOS 以 PowerPoint 匯出）。
2. `uv run scripts/lint_wrap.py out.pptx`：零折行。有違規就改寫文字重跑。
3. `uv run scripts/lint_names.py out.pptx [--deny 倉庫名,服務代號]`：白話命名。
4. 轉 PDF 或圖片**逐頁**看：文字不溢出、不折行、不被截斷、不重疊；lint 以字寬估算，字型不同會有差異。
