# 畫分層架構圖（draw-layered-diagrams）

一張分層圖寫成一份 YAML 規格，由 `scripts/draw.py` 畫成固定風格的 PNG：色票、版面與字級都在引擎裡，任何主題畫出來都像同一系列。規格是圖的唯一來源，PNG 隨時由它重建。

## 先讀

- 消費端 repo 的 `AGENTS.md`：它的圖檔位置、命名與提交規則優先於本技能。
- 寫規格前讀 [references/spec.md](references/spec.md)：鍵、方塊上限、字數參考與色票用途。
- 照範例起手：[兩欄對照、虛線層與說明框](assets/examples/osi-bms-iiot.yml)、[單欄與方向箭頭](assets/examples/three-tier-web.yml)。

## 步驟

1. **定層與欄**：一層一條層帶，由上而下排（抽象在上、具體在下，或順著資料流）；要對照兩三套系統時用 `columns`，每層每欄一格。完成：寫得出每一層的名稱、它和上下層的關係，以及每欄代表誰。
2. **查事實**：每個方塊的歸層、標準名稱、埠號、版本與發布狀態，回到一手來源（標準本文、官方登錄表、規格書）核對；協定依它自己的標準歸層，參考模型（如 OSI）只作對照。在規格檔頂端註解寫核對日期與來源。完成：每一句都追得到來源，查不到的就不寫進圖。
3. **寫規格**：照 [references/spec.md](references/spec.md) 寫 YAML，放在圖檔旁、同名 `.yml`；方塊三行分工為標題（名詞）、重點（最該記住的一點）、補充（限定或例子）。執行 `uv run <技能目錄>/scripts/draw.py <規格> --check`。完成：結束碼 `0`。
4. **輸出並目視**：去掉 `--check` 重跑，得到同名 `.png`（或用 `-o` 指定）；打開 PNG 看一遍。完成：PNG 尺寸是畫布的兩倍，重點落在對的層與欄，說明框與箭頭方向表達的是想說的流向。
5. **交付**：文件、簡報只引用 PNG；規格與 PNG 一起提交，消費端的建置說明寫上重畫指令。完成：改圖的唯一做法是改規格後重跑。

## 規則

- **溢字就改寫字句**：`overflow` 擋下時縮短用詞，或把內容挪到下一行（標題 → 重點 → 補充）；字級、間距與方塊高度是風格本身，保持引擎預設。
- **色彩表達語意**：相鄰層不同色，同一個意思在系列圖裡用同一色；`dashed` 只給標準之外、延伸或願景的層；說明框只寫一句層與層之間流動的東西。
- **一張圖一句結論**：`footer` 寫讀者看完要帶走的那句話，引擎自動加 ★。
- **交付格式只有 PNG**：文件、簡報引擎與 LaTeX 都讀得了，無損壓縮讓文字與細線保持銳利；`--svg` 只供除錯，不進版控。
- **範圍是「層」**：節點之間有大量連線的流程圖、時序圖、ER 圖交給 Mermaid 類工具，本技能專注分層與分層對照。
