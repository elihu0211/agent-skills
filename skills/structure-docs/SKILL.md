# 文件結構（Diátaxis）

每份文件只做一件事。先選類型，再動筆。

| 類型 | 讀者想要 | 寫成 | 不放 |
|------|----------|------|------|
| 教學（Tutorial） | 邊做邊學，從頭到尾 | 有順序的步驟，結果看得見 | 背景、選項 |
| 操作指南（How-to） | 完成一件任務 | 給有能力的讀者的步驟 | 教學、理由 |
| 參考（Reference） | 查東西 | 精簡、結構與被描述的對象一致 | 指示、意見 |
| 說明（Explanation） | 理解為什麼 | 散文、取捨、被否決的選項 | 要執行的指令 |

來源：[diataxis.fr](https://diataxis.fr)。決策紀錄屬於「說明」。

## 規則

1. **一個檔案一種類型**：需要兩種就拆開，用連結而非重複。
2. **每份文件登記**在該 repo 的 `docs/README.md` 並標明類型；索引不存在就建立。它是唯一索引，`AGENTS.md` 不列檔案。
3. **會漂移的值指向來源檔**（版本、數量、主機名稱、檔案清單）。必須釘選的值只在使用它的步驟寫一次，並附理由。
4. **決策只增不改**：每筆帶狀態（已採用、規劃中、接受的缺口、已取代）。要改就新增一筆，並把舊的標為已取代。
5. **文件與它描述的程式碼或清單在同一個變更裡一起改。**
6. **保持簡短**：讀者無法據以行動、也無法在別處查到的內容就刪；深入內容連到官方文件。

## repo 慣例優先

消費端 repo 的 `AGENTS.md` 若自訂文件結構或風格（語言、編號、建置工具），照它。文件是單一體裁出版物的 repo（例如專著文庫）不必套用四分法。
